### 1.2 Make the site build

0. **Install the mermaid theme.** `docusaurus.config.ts` declares `themes: ['@docusaurus/theme-mermaid']`, but the classic preset does not include it and Phase 0 never added it — it is in neither `package.json` nor `pnpm-lock.yaml`, so the build dies on module resolution:

1. `website/tsconfig.json` — replace with:
   ```json
   {
     "extends": "@docusaurus/tsconfig",
     "compilerOptions": {
       "strict": true,
       "noUncheckedIndexedAccess": true,
       "ignoreDeprecations": "6.0"
     },
     "exclude": [".docusaurus", "build"]
   }
   ```
   Why: TS 6 errors on `baseUrl` (TS5101) before type-checking anything; `@docusaurus/tsconfig` still sets it, hence `ignoreDeprecations`. `noUncheckedIndexedAccess` makes `versions[0]` and `syncState.versions[v]` honestly `| undefined`.

2. `website/docs/index.md` — placeholder so the docs plugin has one page:
   ```md
   ---
   title: HarborRAG documentation
   sidebar_position: 0
   ---
   Content on this site is synced automatically from
   [`cbtw-apac/HarborRAG`](https://github.com/cbtw-apac/HarborRAG/tree/main/docs).
   First sync pending.
   ```
   The opening `---` must be line 1. A note or heading above it silently destroys the frontmatter: the `title`/`sidebar_position` keys then render as body text and the sidebar order is ignored, without the build failing. If you want a "this is a placeholder" banner, put it *after* the closing `---` as a Docusaurus admonition (`:::info … :::`) — GitHub's `[!IMPORTANT]` alert syntax is not rendered by Docusaurus.

3. `website/src/pages/index.tsx` — minimal landing (the designed one comes in Phase 6):
   ```tsx
   import type { ReactNode } from 'react';
   import Link from '@docusaurus/Link';
   import useDocusaurusContext from '@docusaurus/useDocusaurusContext';
   import { useLatestVersion } from '@docusaurus/plugin-content-docs/client';
   import Layout from '@theme/Layout';

   export default function Home(): ReactNode {
     const { siteConfig } = useDocusaurusContext();
     const docs = useLatestVersion(undefined);   // pluginId is a required positional
     return (
       <Layout title={siteConfig.title} description={siteConfig.tagline}>
         <main style={{ padding: '6rem 1rem', textAlign: 'center' }}>
           <h1>{siteConfig.title}</h1>
           <p>{siteConfig.tagline}</p>
           <Link className="button button--primary button--lg" to={docs.path}>Read the docs</Link>
         </main>
       </Layout>

   }

While `versions.json` is `[]`, `current` is the only version and it has `path: 'next'`, so the docs are at `/docs/next` and `/docs` does not exist — the strict build reports `Broken link on source page path = /: -> linking to /docs`. It already includes `baseUrl`, which `<Link>` handles — the theme's own version dropdown does the same thing.

## Phase 2 — Ingest script (`main` channel)

Goal: `make sync-local` turns a local HarborRAG checkout into `website/docs/` + `website/sidebars.ts`, deterministically, and the strict build passes on the real content. This is the bulk of the work; it is split so each sub-step has a unit test.

Reference material in HarborRAG (read before coding): `website/builder/markdown_links.py` (link rules), `website/builder/markdown_toc.py` (TOC parsing), `website/check_publication.py`, `website/check_branding.py`, `website/check_docs_publish_path.py` (what counts as published), `docs/TOC.md`.

**MDX 1 compat is off** (consequence of `future: { v4: true }` from step 1.2.8). `mdx1CompatDisabledByDefault` flips `markdown.mdx1Compat` from `{comments: true, admonitions: true, headingIds: true}` to all-false, and Docusaurus 3 runs `.md` through MDX. None of HarborRAG's 29 files has ever been through an MDX pipeline, so whatever MDX 1 used to tolerate now fails the strict build at 2.10: HTML comments (`<!-- … -->`), and bare `{` or `<` that MDX reads as an expression or a JSX tag. Add an `mdx.py` sanitiser to the pipeline (step 8 in `02_…` §3) rather than discovering this one file at a time — strip HTML comments, escape stray braces and angle brackets, hard-error with the source path on anything ambiguous. If some source file genuinely needs the old behaviour, the escape hatch is `markdown: { mdx1Compat: { comments: true } }` in the site config, not a weaker guard.

Input facts (surveyed at 2.0.0a1): 29 markdown files under `docs/`, no frontmatter, no images; links leaving `docs/` are only `../../CONTRIBUTING.md` style root files and `../packages/<name>/README.md`; absolute links to `github.com/cbtw-apac/HarborRAG/...` exist and must be left alone; `TOC.md` has five `##` sections (Getting started, User guides, Developer guides, Package reference, Project) with nested `-` items and links to `../packages/*/README.md`, `../CONTRIBUTING.md`, `../SECURITY.md`, `../CHANGELOG.md`, `../LICENSE`.

### 2.2 Models and CLI

`models.py` — frozen dataclasses mirroring the TypeScript types in `docusaurus.config.ts` (keep field names identical, they are serialised to `sync-state.json`):

```python
Channel = Literal["main", "prerelease", "stable"]

@dataclass(frozen=True)
class SyncEntry:
    label: str
    channel: Channel
    source_ref: str | None
    source_sha: str | None
    synced_at: str | None          # ISO-8601 UTC

@dataclass(frozen=True)
class SyncState:
    current: SyncEntry
    versions: dict[str, SyncEntry]  # "2.0" -> entry

@dataclass(frozen=True)
class IngestRequest:
    source: Path; site: Path; channel: Channel
    product_version: str            # "2.0.1" | "2.1.0a1" | "auto" (read root pyproject)

    target_path: Path       # relative to docs target dir, e.g. users/chat/README.md
    title: str
    body: str
    frontmatter: dict[str, object]
```

|---|---|

## Phase 3 — `sync.yml` (manual trigger first)

### 3.1 Tokens **[decision + admin]**

Two GitHub accounts, A ≠ B (see `02_…` §6.2 table). Create fine-grained PATs scoped to this repo only; store as `DOCS_SYNC_TOKEN` (A) and `APPROVER_PAT` (B) in Settings → Secrets → Actions. Both accounts need Write on the repo. Record expiry dates in the README runbook section. Also add `TEAMS_WEBHOOK_URL` (same value as HarborRAG uses).

**Two settings in the live `main — protected` ruleset will shape how the bot behaves. Read them before debugging a stuck sync PR** (state confirmed 16 Sep 2026 via `gh api repos/cbtw-apac/harborrag-doc-website/rulesets/23526717`):

| Ruleset setting | Value | Consequence for `sync.yml` |
|---|---|---|
| `require_extra_approval_for_unattributed_changes` | `true` | A PR containing commits GitHub cannot attribute to an account needs a **second** approval — auto-merge then stalls even with accounts A and B configured. Set `create-pull-request`'s `committer`/`author` to account A's GitHub name and its `@users.noreply.github.com` address so every sync commit is attributed. |
